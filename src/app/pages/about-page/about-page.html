About

Compare AI model answers against a rubric, pick a winner, and draft an improved response.

  • Create evaluations with prompts and answers
  • Score answers with a rubric table
  • Mark a winner and capture an improved answer

Automation by page

Each step of the pipeline runs on a specific page. Run them in order, or use only the steps you need.

  • Create Full automation that generates title and prompt when needed, then model answers, AI scores, a winner, and an improved answer in one run.
  • Edit Generate model answers from your prompt.
  • Compare Score answers against the rubric and pick a winner.
  • Improved Draft an improved answer from the winning response.

How to add rubric criteria

  1. Open an evaluation from the dashboard and go to Edit.
  2. In Rubric criteria, enter a criterion name (for example Accuracy), an optional description of what a strong score looks like, and the max points for that row.
  3. Examples: Accuracy, Clarity, Completeness, Relevance, Safety.
  4. Click Add criterion. Repeat for each row you want in your rubric.
  5. Add model answers in the right column, then open Compare to view the rubric table and mark a winner.

How to add model answers

  1. Open an evaluation from the dashboard and go to Edit.
  2. In Answers, enter a model name (for example GPT-4) and the model answer.
  3. Click Add model answer. Repeat for each model you want to compare.
  4. Open Compare to view the rubric table and mark a winner.

How to make an improved answer

  1. Read all answers.
  2. Score them using your rubric.
  3. Pick the best answer.
  4. Note what the best answer still lacks.
  5. Borrow useful parts from other answers when helpful.
  6. Remove weak parts, confusing wording, or incorrect claims.
  7. Rewrite a cleaner final answer.
  8. Open the evaluation and go to Improved.
  9. Fill in Winning answer, What was good about it?, What was missing or weak?, Useful parts from other answers, and Improved final answer, then click Save improved answer.

Server setup

AiEval reads server configuration from a .env file in the project root. Copy .env.example to .env and set at least MONGODB_URI. API keys for cloud providers are optional fallbacks when Ollama is unavailable.

You can change the performance preset (Balanced / Fast) in Settings → Models without editing .env. New runs pick up the choice; in-flight automation keeps the preset it started with. After an API restart, LLM_PRESET in .env is used again.
